Disk space, the SDK folder, and uninstalling SiliconPlay

By Ryan Gibo · Updated 12 November 2026

SiliconPlay’s DMG is the small part. The large part is the Android SDK download: Google’s command-line tools, the Apple silicon emulator, platform-tools, and the Play arm64 system image. That pile stays when you delete the app, because it is not a hidden driver and it is not a cache I am allowed to sneak out from under you. This page is what each pile is, how to tell them apart, and the order to delete them if you actually want the disk space back.

The app is for Apple silicon, M1 through M6, including Pro, Max, and Ultra. It is not compatible with Intel Macs. I have tested it on macOS Tahoe and macOS 27 Golden Gate. Disk layout does not change by chip.

Three piles

The app

SiliconPlay.app lives in Applications if you dragged it there from the DMG. Deleting that bundle removes the Mac app. There is no kernel extension to approve on the way out, and no background service to unload. Quit the app first so you are not deleting a running copy.

The SDK folder

This is the folder you chose when the first run said it would download Android, or the existing SDK you pointed at because it already contained emulator, adb, and sdkmanager. If you pointed at a SDK you use for Android Studio, that folder is not “SiliconPlay’s.” Deleting it will break Studio too. If SiliconPlay created the download in a folder you made for it, that folder is the one that holds the emulator and the system image for this app.

I am not going to publish a single path like “it is always ~/Library/Android” because the app asks you where to put it. You picked. If you do not remember, Pro Mode shows more of the main window, including hardware and diagnostics, and the first-run choice is the fact to recover. Pro Mode is in the toolbar, the View menu, and Settings. It is off until you turn it on. I will not invent a “reveal SDK in Finder” chord. If the menu on your build has one, it is drawn there. If I have not verified the chord, it is not in this article.

Application Support

SiliconPlay’s own files are under ~/Library/Application Support/SiliconPlay. That is the app’s folder, separate from the SDK download. Keymaps and the app’s own state live on the SiliconPlay side of that line. The system image does not.

What a delete does not do

  • It does not sign you out of Google Play on Google’s servers. The tablet was a device on the account. Remove it from the account on Google’s side if you want it gone from the device list. The password was never sent to the Mac app.
  • It does not delete some other emulator’s files. BlueStacks, MuMu, Studio, and UTM keep their own directories.
  • It does not remove Homebrew’s JDK if you installed openjdk@17 because setup asked. That JDK is Homebrew’s. Leave it if other tools use it.
  • It does not erase a guest you created and then pointed at a shared SDK. Know which folder is shared before you empty it.

An order that matches the piles

  1. Quit SiliconPlay. If an instance is running, stop it first.
  2. If you might want the games again, confirm cloud saves or accept the loss. I cannot export another format for you in version 1.0.0. The guest does not mount a host folder, so there is no live disk in Finder to copy. Files you pushed with adb are in /sdcard/SiliconPlay on the guest, which goes away with that image.
  3. Delete SiliconPlay from Applications if you want the app gone.
  4. Delete ~/Library/Application Support/SiliconPlay if you want the app’s own files gone.
  5. Delete the SDK folder only if it is the one SiliconPlay downloaded for itself and nothing else points at it. If Studio uses it, do not.

The inverse order is how people delete the SDK, discover Studio broke, and then re-download gigabytes they still needed. Look at the folder before you empty it. If you see a tree you did not create, stop.

How big it is

I am not going to print a byte count and let it rot. The Play arm64 system image plus the emulator and platform-tools is a real download, large enough that a half-finished copy and a finished copy are a disk problem, not a rounding error. A second instance does not always mean a second full image download, but it does mean a second guest’s data. If you created a rooted APIs tablet beside the Play tablet, you have two guests. Removing one instance inside the app is not the same as deleting the SDK folder.

If the first download failed halfway, the folder can be large and still unbootable. That is not a reason to download a second copy into a second folder and keep both. Delete the broken folder you created for the attempt, then run setup once into a folder you mean to keep. The JDK message is separate. brew install openjdk@17 does not replace a truncated image. It unblocks the package step the app named.

Reinstalling later

Drag the app back to Applications and point it at the SDK folder if you kept one. If the folder still has emulator, adb, and sdkmanager, you can skip fetching a second copy. If you deleted the image, you will download it again. Your Play sign-in does not survive the deleted image. You sign in again on the new tablet. Keymaps in Application Support do not survive if you deleted that folder. You place buttons again. That is the cost of a clean disk, and it is a better outcome than a mystery folder you are afraid to touch.

Shortcuts that matter while you are looking at the main window

You are not in the game. You are deciding what to delete. The install chord is still the first line, because the shortcut list is a list and Cmd+I stays at the top even when you are not installing.

Chords that are easy to hit by accident while cleaning up
KeysWhat it will do if an instance is up
Cmd+IImport an APK into the running instance. Do not press it while you are sorting files unless you mean to install one.
EscapeLeave fullscreen, or Back.
Shift-EscapeRelease virtual fingers. Harmless if you are not in a game. Useful if you alt-tabbed out of one.

Start, stop, and create instance are in the main window with Pro Mode off. I am not assigning them chords here. The menu draws those chords, and this build does not store them as a separate string I can quote. Open the menu on your copy.

FAQ

I deleted the app and a huge folder remains. Is that a leftover driver?

No. It is the SDK download, or a SDK you already had. There is no kernel extension in this app.

Can I move the SDK folder to an external disk?

Only if you are willing to point the app at the new place and that disk is mounted when you start. I have not certified external disks. If the volume is asleep, the emulator will not be where the app left it. Try it if you need to, and tell me the macOS version and the chip if it fails.

Does emptying Trash remove the guest from my Google account?

No. Account device lists are Google’s. Trash is the Mac.
