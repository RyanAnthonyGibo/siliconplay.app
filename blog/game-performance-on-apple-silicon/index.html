Game performance in SiliconPlay: what to change, and the one measurement I trust

By Ryan Gibo · Updated 12 November 2026

I get asked for a performance guide that looks like a settings dump. Version 1.0.0 does not have that dump. There is no fps cap to type in, no guest RAM field I am willing to document, and no per-chip profile. What I have is one measured machine, a graphics path I can describe, and an order of changes that does not invent a benchmark.

SiliconPlay is built on the official Android ARM64 emulator. The graphics translation libraries are rewritten for compatibility and frame rate. Vulkan is drawn by Metal. Shaders compile in safe math mode so foliage renders correctly. That path is the same on every supported Mac: Apple silicon, M1 through M6, including Pro, Max, and Ultra. It is not compatible with Intel Macs. I have tested the app on macOS Tahoe and macOS 27 Golden Gate.

The only numbers

On a MacBook Pro with M3 Max, one demanding 3D game reached up to 60 fps, at render resolutions up to 2560×1440, with 7–43 ms from key to game. Results vary by game, Mac, and settings. I have not published the same test for other chips or other games. If a page, including an old one of mine, is read as “every title hits 60,” that reading is wrong. Up to 60 in that one case is the claim. The range on input, 7–43 ms, is already a range, which is what a real measurement looks like when the game is doing different work.

The tablet panel is 1920×1080 at 320 dpi. That is not the 2560×1440 figure. The panel is the size of the Android display version 1.0.0 creates. The render figure is how far that game’s own resolution was pushed on that Mac. Do not “set SiliconPlay to 2560×1440.” There is no such control in the sentence I just wrote.

The order I use when a game stutters

  1. Look at the Android home screen. If the launcher is smooth and the game is not, you are tuning a game, not reviving a dead emulator.
  2. Open the game’s own graphics menu. Drop resolution or effects one step. Play for a minute. This is the change that most often matters, and it does not require me to ship a slider.
  3. Hide the on-screen buttons with Command-Shift-G if you are trying to see the picture. The buttons are input, not a renderer. They can cover the thing you are judging.
  4. Stay on one instance. A second tablet is a second Android. Syncing input across instances is a real action in the Shortcuts list, and it is the wrong tool when you are asking “how fast is this game.”
  5. Quit other heavy Mac apps if you are on a base chip and you want a cleaner reading. I will not turn that advice into a percentage. I have not measured one.
  6. Only after that do I talk about the chip. Newer chips in the M1–M6 line have more headroom. Headroom shows up first in heavy 3D. An M1 running a light game is a normal, supported outcome. The per-chip page, with no fake table, is settings by chip.

What I will not tell you to toggle

  • Safe math mode. It is why foliage renders correctly. It is not a fps cheat you turn off.
  • A kernel extension. There is not one. Nothing in System Settings named SiliconPlay is waiting to “unlock performance.”
  • A background service. Quitting the app quits the app. Leaving a service running is not how this build works, so there is nothing to disable for speed.
  • Root. Root is for development on the Google APIs image. It is off by default. It is not a performance mode, and the Play image refuses adb root anyway.
  • Another emulator’s “high FPS” preset. Those presets are not files this app loads.

Input latency is not frame rate

The 7–43 ms figure is key to game, on that M3 Max, in that game. It is not a promise that every tap feels the same, and it is not something you configure. If keys feel late, check where they are going before you blame the GPU. A key that became text, a key that hit the Mac menu, a button mapped to the wrong corner, and a finger that stayed down all feel like “lag” and none of them are frame time. Click the Android image. F12 or Command-K switches Typing and Game keys. Shift-Escape releases every virtual finger. F10 drops you back to direct touch when a menu wants a finger. The diagnosis is when keys go to the wrong place.

Cmd+I does not belong in a performance pass. It installs an APK. I am listing it first anyway, because every shortcut list on this site starts there, and because people mash it when they are frustrated.

Resolution, in one place

Three different “resolutions” get mixed up in mail:

  • The Mac desktop. Scaled or not, I have not published a fps delta for it.
  • The Android panel, 1920×1080 at 320 dpi, landscape, auto-rotate off. That is the guest display this version creates.
  • The game’s internal render size, which on the measured M3 Max title went up to 2560×1440. That control, when it exists, is in the game.

If the game has no internal scale and it looks soft, I do not have a hidden supersampling switch to hand you. Say so in a report, with the title, and I will tell you if version 1.0.0 has anything to add. I will not make one up for this article.

Heat and the rest of the Mac

A laptop will get warm if a 3D game is actually working. I am not going to give you a fan curve. If the machine is thermally limited, you will see it in the game and in the Mac, and lowering the game’s settings is still the first edit. A desktop Mac in the same chip family has more thermal room than a thin laptop. I have not published a side-by-side, so that sentence is a description of the machines, not a result from my spreadsheet.

Fullscreen is a view option, not a performance mode. I have not measured fullscreen against windowed. Use fullscreen when you want the game in your face. Escape leaves it. I will not claim it adds frames.

When the picture is wrong, not slow

A missing texture, a black guest, or foliage that is a flat color is a different bug from a low frame rate. Home screen fine and game black means start with the game and the package, including whether it shipped an ARM64 library. Home screen black means the instance did not come up. That is the first-run and download checklist, not a quality slider. The common-problems order is the one I want you to walk. The graphics write-up is Vulkan, Metal, and safe-math shaders.

FAQ

Can you add a high-fps mode?

I am not announcing features on this page. Version 1.0.0 does what this page says. The measured ceiling I will cite is the M3 Max result above.

Does Metal mean every game is GPU-bound on the Mac?

No. Some games are heavy on the guest CPU, some on the GPU, some on their own server. I do not have a per-game breakdown. Lowering the game’s settings is still the experiment that teaches you which.

Will more instances lower fps?

A second instance is more work. I have not published a number for how much. If you are measuring one game, run one instance.

Is 7 ms the input lag I should expect?

No. The measurement was 7–43 ms on that Mac in that game. Expect the range to move when the game or the Mac changes. If a key does nothing for a full second, that is not this number. That is focus, mode, or a stuck finger.
