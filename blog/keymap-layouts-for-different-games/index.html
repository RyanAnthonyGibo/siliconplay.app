On-screen controls for different Android games on a Mac

By Ryan Gibo · Updated 12 November 2026

Most Android games expect a finger. SiliconPlay’s default is that finger: direct touch, nothing mapped, until you accept a layout. The mapper is the same tool on every game. What changes is where you put the buttons, and whether a given screen wants keys at all. This page is how I lay that out for the kinds of games people actually open, without pretending I ship a preset for every title on Play.

The app is SiliconPlay. I wrote the Mac side, including the on-screen controls, around the official Android ARM64 emulator. It runs on Apple silicon from M1 through M6. It is not compatible with Intel Macs. I have tested it on macOS Tahoe and macOS 27 Golden Gate.

Before you edit anything

Start the instance. Click the Android image so keys have a target. If you are in a text field, the toolbar switches to Typing and your keyboard becomes text. That is correct for a login box and wrong for a fight. F12 or Command-K flips Typing and Game keys. F10 forces direct touch when a menu is fighting your keymap.

A suggested preset, when the app offers one for a known game, stays off until you accept it. The generic preset, MMORPG (WASD), is not tied to one game. Apply it, then move, resize, and rebind. Full editing mechanics are in keyboard mapping on Mac. This page is the part about what to aim the buttons at.

A controller does not get a private map. It presses the same on-screen buttons. If a button is in the wrong corner for your thumb, move the button. Do not go looking for a second gamepad profile I have not documented.

A game that moves with WASD and taps skills

This is the case the default file already matches. Apply MMORPG (WASD). Put the stick where the game’s movement area is, which on a lot of mobile titles is the left half of the screen, not a tiny D-pad in the corner. Size it so a full press does not also hit a UI button beside it. Put J on the primary action. Put 1–6 on the skill tray, or delete the ones the game does not have by not using them. I would rather you have two well placed buttons than six covering the fight.

Hold versus tap matters. Attack in this preset is held. If the game treats a held finger as a continuous attack, that is what you want. If the game opens a charged menu when the finger stays down, you will hate J until you rebind that button to a tap. The mapper can rebind. I am describing the default, not locking you to it.

A game that is click-to-move

WASD is the wrong first idea. The game wants a finger on the ground. Direct touch, or F10 if a keymap is already loaded, is the honest control. You can still map one or two keys onto the skill buttons at the edge of the screen, and leave movement as a click. Do not stretch the WASD stick across the whole world and then be surprised that walking and camera-dragging are the same gesture. They are the same gesture in that genre. A keymap will not invent a right-mouse camera the game does not have.

A twin-stick game

You want two regions: move, and aim or fire. The default file has one stick. Use it for move. Put a held button, the attack chip, under your other hand, in the region where the game reads the aiming finger. If the game uses a second virtual stick rather than a button, a single held button will feel wrong, and you should say so by editing: place the control where the second stick’s touch area is, and test in the tutorial, not in a live match. I am not going to claim the default preset is a twin-stick layout. It is not.

A controller helps here because the physical sticks already exist. They still drive the on-screen controls, so the on-screen stick has to sit on the game’s move area or the left gamepad stick will drag the wrong pixels.

A menu, an inventory, or a shop

Switch to direct touch or Typing. Game keys in a menu produce accidental walks and skill casts. F10 is the short way back to a finger. When a search box is focused, Typing is what you want, and the app switches to it for a focused text field. If it did not, use F12 or Command-K. Then click the image again when you go back to the fight, and switch to game keys on purpose.

A rhythm game or anything that cares about a exact tap

Mapping a key to a lane can work. It can also feel late if the button’s hit region is fat and you are hitting the edge. Shrink the button to the lane. Do not stack six skill buttons on top of the judgment line. I have not published a rhythm-game latency number. The 7–43 ms key-to-game range is from a demanding 3D game on an M3 Max, not from a note highway. If a rhythm game feels off, say which one and whether direct touch felt different from the key. That comparison is more useful to me than a request for a global offset I have not shipped.

Per game, saved how you leave it

Layouts are per game in the sense that you edit the buttons for the game in front of you and you can keep a keymap for it. I am not going to describe an export format I have not documented as a stable file you should hand-edit. If you download a keymap someone posted, treat it as untrusted until you look at where the buttons sit. A layout for a different resolution, or for a different skin of the same game, will put J on a chat button. The warning is the same one in WASD, the gamepad, and the on-screen buttons.

Pro Mode shows keymaps among other diagnostics. You do not need Pro Mode to play or to move a button. It is off until you turn it on, from the toolbar, the View menu, or Settings.

FAQ

Do I have to map keys?

No. Direct touch is the default and it is a complete way to play. Mapping is for when you want a keyboard or a pad.

Why did my keymap not load for this game?

Because nothing loads until you accept it. A known-game suggestion is still a suggestion.

Can one layout serve every game?

The WASD preset can start a lot of them. It will be wrong for click-to-move and for menus. Switch modes instead of forcing one stick onto every screen.

The button works in the tutorial and not in combat.

The game moved the touch target. Reposition the button on the combat HUD, not on the tutorial HUD. Shift-Escape if a finger from the tutorial is still down.
