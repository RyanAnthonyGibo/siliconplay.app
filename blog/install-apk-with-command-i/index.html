Install an APK on SiliconPlay: Command-I, drag and drop, and adb

By Ryan Gibo · 3 November 2026

Most of the time you will install from Google Play. When you have a file instead, SiliconPlay gives you three ways onto the Android 16 tablet, and one hard stop. This page is those three ways, the order they have to happen in, and the packages version 1.0.0 will not install no matter which way you try.

The instance has to be running

Start the tablet before you install. The main window’s Start button is that step when Pro Mode is off. Create New Instance is how you make another one. An install sent at a stopped instance has nowhere to go. I keep saying this because it is the failure that looks like a broken file and is not one.

The tablet you want for ordinary installs is the Play image created on first run: landscape, 1920×1080, 320 dpi, auto-rotate off, named Android 16 Tablet. A rooted tablet is a different image and does not include Play Store. You can still put an APK on it. You just will not then open Play to update that same package. See root and the Play image if you are about to mix those up.

The three ways, with Command-I first

These are the install actions version 1.0.0 actually has. I am not adding gestures from other emulators.

  1. Command-I. Import an APK and install it into Android. This is the shortcut to learn first. It is also the first row in the shortcut list.
  2. Drop the file. Drag an .apk onto the running instance. Same install, no chord to remember.
  3. adb. Install from the terminal with the platform-tools that came down with the SDK. Files copied that way go to /sdcard/SiliconPlay.

Command-key shortcuts stay with macOS. They are not typed into the game. Command-I is one of those. You do not have to click the Android image first, and you do not have to be in Game keys. If a text field inside Android is focused, leave it alone and press Command-I anyway. The import is a Mac command, not a character the game receives.

What this version will not install

Split APKs and XAPK archives are not installed by this version. A bundle that is only those formats will not go on, whether you drop it, press Command-I, or point adb at it. If the only file you have is an .xapk, or a set of split APKs, this build will not assemble them for you. I am not going to describe a manual unzip-and-install recipe I have not shipped. Get a single .apk, or install the app from the Play Store on the Play image.

An APK with no ARM64 build will not run even if the install appears to start. The tablet is ARM64 Android 16, running on the Mac’s ARM cores through Apple’s Hypervisor framework. There is no second architecture hiding behind it. Most current apps include an ARM64 build. Older packages sometimes do not. That case is written up in APKs that do not install or open.

adb, without pretending the disk is shared

Platform-tools is part of the first-run download, or part of the SDK folder you pointed at. adb from that folder is the adb SiliconPlay is using. Copies made with adb land in /sdcard/SiliconPlay. That path is inside the tablet. It is not a Finder folder.

These images do not mount a host folder as a live disk. If you were expecting a shared directory to appear in the Android files app because you configured one in another product, it will not. Move the file with adb, with Command-I, or with a drop. Do not spend an afternoon looking for a mount setting this version does not have.

You do not need Android Studio in front while you do this. The IDE is useful when you want the rest of the SDK tools and a project. It is not required to install a file and tap through it. The longer developer path, including the JDK message, is in testing a build without Android Studio.

After the package is on the tablet

Open it from the Android home screen the way you would on a phone. Direct touch is the default, which is what you want for a menu, a login, or any app that is just a UI. The pointer is a finger. Click the Android image so later keystrokes go to the keymap, if you load one.

A known game may offer a community preset. The preset stays off until you accept it. No keymap is loaded just because the APK installed. Until you accept a suggestion, direct touch stays on. The generic layout you can apply yourself is named MMORPG (WASD). It is not tied to a package, so it is not suggested automatically. Editing it is covered in WASD, a gamepad, and the on-screen buttons and in the existing keyboard mapping guide.

If you only needed to know whether your build installs and opens, you can stop here. You do not have to turn root on. Root is optional and off by default. Turn it on only when you need adb root, and expect a second tablet on the Google APIs image when you do.

When the install does nothing

  • Confirm the instance is started. Stopped is the usual reason.
  • Confirm the file ends in .apk and is a single package, not an XAPK and not a split set.
  • Confirm you are on the tablet you think you are on, if you have created more than one instance.
  • If adb cannot see a device, you are not talking to the platform-tools that belong to the SDK folder SiliconPlay is using. Starting the instance again is the first check, not a new USB cable. There is no phone plugged in.
  • If the package installs and immediately cannot run a library, suspect a missing ARM64 build before you suspect Metal.

SiliconPlay does not modify the game. Optional root does not change that sentence. Follow the game’s own terms if you sign in with a real account. I would rather you read that twice than discover it from a ban notice I cannot undo.

Shortcuts that sit next to install

Command-I is the install shortcut. The others are not installers, but you will hit them while you are testing a package, so they belong on the same page. This is the set version 1.0.0 writes out in words. Command-I stays first.

Shortcuts you will use while installing and trying an APK
KeysAction
Command-IImport an APK and install it into Android.
F12, or Command-KToggle Typing and Game keys.
Command-Shift-GShow or hide the on-screen game-button overlay.
EscapeLeave fullscreen. Outside fullscreen, Android Back while the display is focused.
Shift-EscapeRelease every virtual finger.
F10Switch to direct touch.

A few more actions are named in the Shortcuts list without a readable key string in this build: start or stop the selected instance, toggle fullscreen, save a screenshot, start or stop screen recording, and others. I am not going to invent those chords. Open Shortcuts in the app and read the key next to the label.
