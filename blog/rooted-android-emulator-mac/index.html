A rooted Android emulator for developers on Apple Silicon Macs

By Ryan Gibo · 27 October 2026

If you just want to see whether an APK runs, opening a full IDE is a lot of ceremony. SiliconPlay is a small Mac app in front of a real Android tablet: ARM64, Android 16, on Apple Silicon. I built the app from scratch. Under the hood it uses the official Android Emulator. The license notices name that emulator and the SDK pieces that come with it.

It is only for Apple Silicon, M1 through M5 and newer chips in that line, including Pro, Max, and Ultra. It is not compatible with Intel Macs. I have tested it on macOS Tahoe. If you try another macOS version, tell me how it went. I would rather hear that than guess.

What you actually get

SiliconPlay does not ship Google’s emulator or the system image inside the download. The first run asks you to download Android and start. That step accepts the Android SDK license on this Mac, then downloads Google’s command-line tools, the Apple silicon emulator, platform-tools, and the Play arm64 system image into an SDK folder you choose. It creates one landscape tablet named Android 16 Tablet and opens it in its own window. The default tablet is 1920×1080 at 320 dpi, landscape, with auto-rotate off, on the Android 16 Play image.

Google Play shows up after that image is in place. It is not a store I bundled. On the Android home screen, open Play Store and sign in. SiliconPlay never sees that password. If you already have an SDK with emulator, adb, and sdkmanager, you can point the app at that folder instead of downloading a second copy.

If setup stops because macOS has no JDK, the app says so. /usr/bin/java on macOS is a stub. The message in the app points at brew install openjdk@17, then run the package step again.

Install an APK without living in an IDE

Start the instance first. Then drop an .apk file. Split APKs and XAPK archives are not installed by this version, so a bundle that is only those formats will not go on. That is enough for the usual “did my build install and open” check. You do not have to keep Android Studio in front while you tap through the app.

Files copied with adb go to /sdcard/SiliconPlay. These images do not mount a host folder as a live disk, so do not expect a shared directory to appear inside Android on its own.

Pro Mode is off until you turn it on. It lives in the toolbar, the View menu, and Settings. On, the main window also shows hardware, keymaps, and diagnostics. Off, the main window stays on Start, Stop, and Create New Instance.

Root is optional, and it starts off

Root is optional and off by default. Leave it off for a normal Play tablet. Turn it on only when you need adb root.

A rooted tablet uses the Google APIs image, because the Play image refuses adb root. Play Store is not included on that tablet. The APIs image is downloaded the first time you create one. If you need both Play sign-in and root, those are two different tablets, not a switch you can flip on a Play image.

There is no kernel extension and no background service to uninstall later. Delete the app when you are done with it. SDK files stay in the SDK folder you picked. SiliconPlay’s own files are under ~/Library/Application Support/SiliconPlay.

Keyboard, if the app you are testing has no keys

Direct touch is the default, which is usually what you want for a UI you built. If you are clicking through a game, the on-screen keymap and the shortcut list are the other half of this.

FAQ

Is root required?

No. It is optional and off by default. Root uses the Google APIs image. The Play image refuses adb root, and that rooted tablet does not include Play Store.

How do I install an APK?

Start the instance, then drop an APK. Split APKs and XAPK archives are not installed by this version. adb copies go to /sdcard/SiliconPlay.

Do I need Android Studio open?

No. You can install an APK and try it without a full IDE in the way. The app downloads the official emulator and the Play arm64 image, or uses an SDK you already have.

Which Macs and which macOS?

Apple Silicon only: M1, M2, M3, M4, M5, and newer. Not Intel Macs. Tested so far on macOS Tahoe.
