Pro Mode, the SDK folder, and the files SiliconPlay leaves behind

By Ryan Gibo · 3 November 2026

There are three piles of files once SiliconPlay has run, and people delete the wrong one. The Mac app is the thing in Applications. The SDK folder is the place you chose for Google’s emulator, platform-tools, and the system image. SiliconPlay’s own files are under ~/Library/Application Support/SiliconPlay. Pro Mode is not a fourth pile. It is a view on the main window. This page separates them so a reinstall does not surprise you.

What the main window shows when Pro Mode is off

Pro Mode is off until you turn it on. Off, the main window stays on Start, Stop, and Create New Instance. That is enough to boot the Android 16 tablet, quit it, and make another instance. It is the view I expect most people to live in. Turning Pro Mode on does not make the tablet faster, and it does not enable root. Root is a different system image, described in root and the Play image.

You turn Pro Mode on from the toolbar, the View menu, or Settings. On, the main window also shows hardware, keymaps, and diagnostics. The glass bubble on the emulator window does not wait for that switch. The bubble still has edit, overlay, opacity, size, and reset. Drag the bubble to move it. The spot is saved on the profile.

Diagnostics are there to be read when something failed. I am not going to invent a list of log lines or a support code. If a line on that panel names a missing tool, believe the line. The JDK case is the one the app already phrases for you: /usr/bin/java on macOS is a stub, and the message points at brew install openjdk@17, after which you run the package step again.

The SDK folder is a download, not a cache you can ignore

SiliconPlay does not ship Google’s emulator or the system image inside the DMG. First run accepts the Android SDK license on this Mac, then downloads command-line tools, the Apple silicon emulator, platform-tools, and the Play arm64 system image into the folder you pick. If you already have an SDK with emulator, adb, and sdkmanager, you can point at that folder and skip a second copy.

That folder is yours. Deleting SiliconPlay does not delete it. Deleting it while the app is installed means the next start has to download again, or you have to point at another SDK. The Play image and, if you created one, the Google APIs image both live in that SDK world. They are large. Look at the folder size before you blame the Mac app for “taking the disk.” The app in Applications is not the system image.

adb from platform-tools is how copies get to /sdcard/SiliconPlay inside the tablet. The image does not mount a host folder as a live disk. Do not go looking for the SDK folder inside the Android files app. It is a Mac folder.

The Application Support folder

SiliconPlay’s own files are under ~/Library/Application Support/SiliconPlay. That is the Mac-side state: the sort of thing a profile and the app’s own bookkeeping live in. I am not going to itemize every file in that directory for version 1.0.0, because a list I guess at would be wrong the next time a file is renamed. If you are resetting the Mac side and you want the app to start clean, quit SiliconPlay and move that folder aside. Leave the SDK folder if you do not want to download Android again. Leave the Applications copy if you still want the app.

Keymaps you edit are part of using the app, and Pro Mode is one place they show up. The editor itself is available from the bubble without Pro Mode: drag a button, click to rebind, drag the gold dot to resize, Done to save, Cancel to restore. A shared keymap file has to be valid JSON in the format SiliconPlay accepts, or it is rejected.

Uninstall, in the order that matches the piles

  1. Quit the app. Stop the instance first if it is running.
  2. Delete SiliconPlay from Applications. There is no kernel extension to unload and no background service to disable. The app is gone.
  3. If you also want the Mac-side state gone, remove ~/Library/Application Support/SiliconPlay.
  4. If you also want the emulator and system images gone, remove the SDK folder you chose. If that folder is an SDK you use for other work, do not remove it. Pointing SiliconPlay at it did not make it exclusive.

Nothing in that list removes your Google account, and nothing in it reaches into a game account. Sign-in happened inside Play Store on the tablet. SiliconPlay never saw the password. Deleting the image deletes the tablet’s local copy of that session. It does not delete the Google account.

What Pro Mode will not tell you

  • It will not publish a frame rate I have not measured. The only published run is a MacBook Pro with M3 Max: up to 60 fps in a demanding 3D game, render resolution up to 2560×1440, 7–43 ms key-to-game. Results vary. Pro Mode is not that test.
  • It will not change Command-I, F12, or the overlay chord. Those are in the shortcut list regardless of the switch.
  • It will not install a split APK or an XAPK. This version does not install those formats.
  • It will not make the Play image accept adb root.

Shortcuts while you are looking at the main window

Shortcuts that stay available with Pro Mode on or off
KeysAction
Command-IImport an APK and install it into the running Android.
F12, or Command-KToggle Typing and Game keys.
Command-Shift-GShow or hide the on-screen game-button overlay.
EscapeLeave fullscreen, or Android Back when the window is not fullscreen and the display is focused.
Shift-EscapeRelease every virtual finger.
F10Switch to direct touch.

Start or stop the selected instance is a named Shortcuts action without a key string I can quote from version 1.0.0. The button on the main window is Start and Stop. Use the button if you do not want to open the menu. The first-run sequence that fills the SDK folder is in how the first run sets up Android 16.
