When keys go to the wrong place: focus, Accessibility, and stuck fingers

By Ryan Gibo · 3 November 2026

When a key does the wrong thing in SiliconPlay, it is almost never a broken keyboard. The key went to macOS, or it went to Android as text, or it became a touch on a button that is not where the game’s art is, or a previous touch never came up. This page is those four outcomes and the one control that fixes each of them. I am not adding a fifth cause I have not seen in version 1.0.0.

Outcome 1: the key went to the Mac

Command-key shortcuts stay with macOS. They are not typed into the game. Command-I imports an APK. That is correct even when a text field is focused. If you wanted the letter i, you wanted Typing, and you wanted the i key without Command.

Keys still work while the SiliconPlay window is focused. The emulator also has its own window. The first time the app follows that window, macOS asks for Accessibility. Until you allow that, keep the SiliconPlay window focused and the keys still land. If you click the emulator window and the keys start driving a different Mac app, Accessibility was not granted, or the follow has not happened yet. Click back into the SiliconPlay window. Or allow Accessibility for this app in macOS and try the follow again. I am not going to redraw Apple’s Settings panes from memory. The prompt is the one macOS shows. The behavior if you refuse it is the one I just described: focus the SiliconPlay window.

Outcome 2: the key became text

A focused text field switches the toolbar to Typing, and then the keyboard goes to Android as text. That is right for a login and wrong for a fight. F12 or Command-K toggles Typing and Game keys. Look at the toolbar before you rebind anything. If it says Typing and you are holding W expecting to walk, you are typing the letter w into whatever field still has focus. Close the field, or press F12 or Command-K.

The field can switch you into Typing by itself. A game that opens chat has done that. Closing the chat does not always switch you back. Check the toolbar.

Outcome 3: the key became a touch in the wrong spot

Game keys use the keymap, and only after a keymap is loaded. Direct touch is the default. A suggested preset stays off until you accept it. If you never accepted one and never applied MMORPG (WASD), game keys have nothing useful to press. Apply the layout or accept the preset.

If the layout is loaded and the touch hits the wrong button, the position is a fraction of the picture, origin at the top left. Fullscreen changes the picture’s size. Drag the button in Edit layout until it sits on the art. Click a chip to rebind. Drag the gold dot to resize. Done saves. Cancel restores the profile to how it was when you opened Edit. Escape during a rebind cancels the capture only.

The default stick moves from the center of its button while WASD or the arrows are held, and it returns to the center when you let go. If the character walks when you wanted a menu, you are still on the stick. F10 switches to direct touch so a menu can have a real finger. Command-Shift-G hides the overlay if a chip is covering the control you need to see. Empty space on the picture still clicks the game.

Outcome 4: a finger stayed down

Attack on the default layout is J, held. The finger stays down while J is held. If the key-up is lost, the finger stays down after you let go. Shift-Escape releases every virtual finger. That is the chord. It is not Escape. Escape leaves fullscreen, and when the window is not fullscreen it is Android Back while the display is focused. People press Escape, the game goes Back, and the stuck finger is still down. Press Shift-Escape.

A repeat chip that you added in the editor will keep firing because you asked it to. Shift-Escape releases fingers. It does not delete the chip. Open Edit and remove the repeat if that is what you added.

A pass that takes a minute

  1. Click the SiliconPlay window so focus is not in some other Mac app. If following the emulator window matters to you, allow Accessibility when macOS asks.
  2. Read the toolbar. Press F12 or Command-K until it matches what you are doing. Typing for a field. Game keys for a layout you have accepted or applied.
  3. If a finger is stuck, Shift-Escape before you touch the keymap.
  4. If the touch is in the wrong place, Edit layout and drag the chip. Do not start by changing the key. The key is probably fine.
  5. If the menu wants a finger, F10.
  6. If none of that matches, and Command-I still installs an APK, the Mac side of the keyboard is fine. Say which of the four outcomes you still see when you write to me, and name the game.

A controller uses the same chips as the keyboard. If the pad does the wrong thing and the keyboard does the right thing on that chip, the binding for the pad is the one to edit, not the Mac’s keyboard settings. The default pad buttons are listed in WASD and the gamepad. The full shortcut article is the keyboard list from version 1.0.0.

This is the same on M1 through M6, tested on macOS Tahoe and macOS 27 Golden Gate. A different macOS version can ask for Accessibility with a different screen. The focus rule does not change: until follow is allowed, keep the SiliconPlay window focused.
