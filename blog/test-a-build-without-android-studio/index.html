Test an APK on Apple silicon without keeping Android Studio open

By Ryan Gibo · 3 November 2026

Android Studio is the right place to edit a project. It is a lot of window for the question “did this APK install and open.” SiliconPlay is a Mac app in front of a real ARM64 Android 16 tablet, using Google’s official Android Emulator underneath. I wrote the Mac app from scratch. You can install a build and tap through it without keeping the IDE in front. This page is that loop, including the places it honestly stops.

What you are borrowing from the SDK, and what you are not

The DMG does not contain the emulator or the system image. First run accepts the Android SDK license and downloads command-line tools, the Apple silicon emulator, platform-tools, and the Play arm64 image into a folder you choose. If you already have an SDK from Android Studio with emulator, adb, and sdkmanager, point SiliconPlay at that folder instead of downloading a second copy. You can then quit the IDE. The emulator process SiliconPlay starts does not need the IDE window to stay open.

The default tablet is landscape, 1920×1080, 320 dpi, auto-rotate off, on the Android 16 Play image, named Android 16 Tablet. That is a real system image, not a screenshot of a phone. Google Play is on that image. SiliconPlay never sees the Play password. A test that needs adb root does not use this image. The Play image refuses adb root. Create the Google APIs tablet for that, and accept that it has no Play Store. Both can exist. They are not a toggle.

If setup stops because there is no JDK, the app says so. /usr/bin/java is a stub on macOS. The message points at brew install openjdk@17. Install it and run the package step again. Android Studio’s embedded JDK is not automatically the JDK that stub is pointing at. Follow the message on screen if it differs from this page. This page is version 1.0.0.

The install loop

  1. Start the instance. Pro Mode can stay off. The main window shows Start, Stop, and Create New Instance.
  2. Press Command-I and choose the .apk, or drop the file on the instance.
  3. Or use adb from the platform-tools in the SDK folder you selected. Copies go to /sdcard/SiliconPlay.
  4. Open the app on the tablet with direct touch. The pointer is a finger. You do not need a keymap to tap through a UI you built.
  5. When you have a new build, install it again the same way. Stop the instance only when you are done, not between two installs, unless the new package needs a clean process you have decided to restart.

Split APKs and XAPK archives are not installed by this version. If your Gradle task only emits splits, produce a single APK for this loop or install another way. I am not documenting a flag I have not shipped. The image also does not mount the project directory as a live disk. adb, Command-I, or a drop are how the file moves.

An APK with no ARM64 build will not run. The tablet is arm64, on the Mac’s ARM cores, through Apple’s Hypervisor framework. Most current apps include an ARM64 build. A build you configured for something else will not start native code here. Why an APK does not open separates that from a bad install.

When the thing you are testing is a game

Direct touch remains the right default for menus. If you need keys, accept a community preset if one is offered, or apply MMORPG (WASD) and move the buttons. The preset stays off until you accept it. F12 or Command-K toggles Typing and Game keys. A focused text field switches to Typing on its own, which is what you want when the build asks for a login.

Vulkan is drawn by Metal, with shaders in safe math mode so foliage renders correctly. The only published performance note is from a MacBook Pro with M3 Max: up to 60 fps in a demanding 3D game, render resolution up to 2560×1440, 7–43 ms key-to-game. Results vary by game, Mac, and settings. I have not published numbers for your project. Do not quote mine as if they were.

Pro Mode, when the UI is not enough

Turn Pro Mode on from the toolbar, the View menu, or Settings when you want hardware, keymaps, and diagnostics on the main window. Leave it off when you want Start, Stop, and Create New Instance and nothing else. The bubble on the emulator window still edits the keymap, the overlay, opacity, size, and reset without Pro Mode. Diagnostics are a view, not a second emulator.

There is no kernel extension and no background service. When the test week is over, delete the app from Applications. The SDK folder stays, which is what you want if Android Studio still uses it. SiliconPlay’s own files are under ~/Library/Application Support/SiliconPlay. Move that folder aside if you want the Mac-side state gone and the SDK left in place. Details are in Pro Mode and the files.

Shortcuts in the test loop

Shortcuts while you install and poke at a build
KeysAction
Command-IImport an APK and install it into the running Android.
F12, or Command-KToggle Typing and Game keys.
Command-Shift-GShow or hide the on-screen overlay.
EscapeLeave fullscreen, or Android Back when not fullscreen and the display is focused.
Shift-EscapeRelease every virtual finger.
F10Switch to direct touch.

Start or stop the selected instance, save a screenshot, and start or stop screen recording are named in the Shortcuts list. The chords are drawn by the menu in version 1.0.0 and are not stored as text I can copy here. A screenshot of a layout bug is still the right artifact. Open the menu and use the action it labels.

The Mac has to be Apple silicon, M1 through M6, and the versions I have tested are macOS Tahoe and macOS 27 Golden Gate. The source of the Mac app is not published. Third-party licenses, including the Android Emulator and QEMU, are on the licenses page and ship inside the app. If a build installs on the tablet and fails only in Studio’s own emulator, say which image each one was using when you write. Those are often not the same Android.
