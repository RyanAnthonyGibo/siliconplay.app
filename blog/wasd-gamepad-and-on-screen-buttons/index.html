WASD, a gamepad, and the on-screen buttons in SiliconPlay

By Ryan Gibo · 3 November 2026

Android games expect a finger. SiliconPlay puts a button on the picture and ties that button to a key, a mouse button, or a gamepad button. That is the whole mapping model. There is no second, hidden controller mode. This page is the generic layout that ships with version 1.0.0, how a controller shares those buttons, and the edit gestures that move a chip onto the art it is supposed to hit.

Nothing loads until you say so

Direct touch is the default. The pointer is a finger, which is what you want until a keymap exists. When a known game is in front, SiliconPlay can offer a community preset. The preset stays off until you accept it. The generic layout is named MMORPG (WASD). It is not tied to a package, so it is not suggested automatically. You apply it to any game, then fix whatever misses.

Click the Android image so the keyboard goes to the keymap. If a text field is focused, the toolbar says Typing and the keys go into Android instead. F12 or Command-K switches between Typing and Game keys. Command-key shortcuts stay with macOS, including Command-I, which imports an APK and does not type the letter i.

Per-game presets replace the generic layout when you accept them. Minecraft’s preset uses left click to break, right click to use, Space to jump, E for inventory, 1 through 3 for the hotbar, and right mouse to look. Until you accept a suggestion, direct touch stays on and the MMORPG keys are not loaded. The same build also ships presets for games such as Genshin Impact, Roblox, Call of Duty Mobile, Clash of Clans, and others. I am not going to pretend one layout fits all of them. Accept the suggestion, play for a minute, and move the chips.

The default bindings

The stick touches down in the center of its button and drags outward while any of its keys is held. It slides back to the center when you let go. These are the bindings in that file, not a suggestion I would like you to memorize from a different game.

The notes on that preset say to adjust it in the editor. Positions are fractions of the game picture, from 0 to 1, with the origin at the top left. They scale when the window changes size. A button that sat on a skill in a small window can sit on the chat log after you go fullscreen, or the other way around. That is geometry, not a lost binding. Open Edit and drag it back.

Move, resize, rebind

Edit layout opens the keymap editor. Drag a button to move it. Click it to rebind a key or a mouse button. Drag the gold dot to resize. You can add a WASD joystick, a camera drag, a tap, a long-press, a swipe, or a repeat. Done saves. Cancel puts the profile back to how it was when you opened Edit. Escape cancels a key capture if you are mid-rebind. It does not close the editor with a save, and it is not Android Back during that capture.

On the emulator window, a glass bubble follows the window. Drag the bubble to move it. Click it for the overlay, opacity, size, edit, and reset. That spot is saved on the profile. Command-Shift-G toggles the overlay. Empty space on the picture still clicks the game, so a missing button is not the only way to tap.

F10 switches to direct touch when a menu wants a finger instead of a mapped button. Shift-Escape releases every virtual finger if one gets stuck down. Attack on J is a hold, so a stuck attack is the case Shift-Escape is for. Skills are taps. If a skill fires twice, look at whether you added a repeat in the editor before you blame the key.

The gamepad presses the same chips

You can bind the face buttons, shoulders, triggers, D-pad, menu, and options buttons when you rebind a chip. The default layout already does this for a few skills and for jump: gamepad X, gamepad Y, the right shoulder, and the right trigger sit on skills 1, 2, 4, and 6, and gamepad B sits on jump. Skill 3 and skill 5 are keyboard-only until you add a button. The controller is not a second scheme. If Game keys are off, the pad is not in a secret mode of its own.

I have not published a list of supported controller models. If macOS sees the pad as a gamepad, the bindings above are the ones the preset already uses. If macOS does not see the pad, SiliconPlay will not see it either. That check belongs in the macOS Bluetooth or USB settings, not in a keymap file.

Files someone else posted

The reliable copy is the one in the app. A layout from somewhere else has to be valid JSON in the keymap format SiliconPlay accepts. A file that is not valid for that format is rejected. Positions in a shared file were drawn for someone else’s screen, so open the editor and line the buttons up with yours even when the file loads. I am not going to promise that a layout made for a different emulator will import. It will not, unless it is already this format.

Pro Mode, in the toolbar, the View menu, and Settings, shows hardware, keymaps, and diagnostics on the main window. It is off until you turn it on. You can edit from the bubble without turning Pro Mode on.
