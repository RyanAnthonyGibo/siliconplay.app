Install from Google Play or from an APK on SiliconPlay

By Ryan Gibo · Updated 12 November 2026

There are two honest ways onto the SiliconPlay tablet: Google Play, on the Play image, or a single APK file. Everything else people try, a split archive, an XAPK, a folder they shared in some other emulator, is a third path this version does not have. This page is how I choose, and what I do when the file I was handed is the wrong shape.

SiliconPlay is the Mac app. Under it is the official Android ARM64 emulator, with the graphics translation libraries rewritten for compatibility and frame rate. The supported Macs are Apple silicon, M1 through M6, including Pro, Max, and Ultra. It is not compatible with Intel Macs. I have tested it on macOS Tahoe and macOS 27 Golden Gate.

Use Play when the title is simply on Play

The default tablet is the Android 16 Play image. Open Play Store on the Android home screen and sign in there. The Mac app never sees the password. Play then delivers a build for this device, which is an ARM64 tablet. That matters. A random APK you downloaded on a Windows PC is often the wrong ABI, or a split set packed for a store client, or both.

Play is also the update path. Cmd+I will not update a store install for you. If Play says the app is outdated, update it in Play. Services the app complains about are updated the same way, on this image, not by a file you drop on the window. The longer notes are in Play services and the sign-in steps are in signing in.

Choose Play too when you care about the account. A purchase, a cloud save, and a ban are between you, the publisher, and Google. SiliconPlay does not modify games. I would rather you install the store build and follow the game’s terms than sideload a repackaged file you cannot explain.

Use a single APK when you have a single APK

Your own build, a game that is not on Play, or a file someone handed you as one .apk: that is the sideload path. The instance has to be running. Then:

Install chords and the neighbors
KeysWhat you are doing
Cmd+IImport an APK and install it. This is the one to learn. The menu labels it Command-I.
Drag and dropThe same install, if you already have the file in Finder and the instance is up.
adb installThe same idea from the SDK’s platform-tools. Reinstall your own build with adb install -r. Files that are not packages, pushed with adb, go to /sdcard/SiliconPlay.
F12, or Command-KAfter it is installed, switch Typing and game keys. Not part of the install.
F10Direct touch, if the first screen is a dialog and a keymap is in the way.

The file still has to contain an ARM64 library if it ships native code. A package with no ARM64 build will not run on this tablet, on an M1 or an M6. Java-only apps are the exception people mean when they say “it has no native library and it opened anyway.” If it uses native code and the ARM64 build is absent, it will not.

Do not use this version for these files

  • Split APKs. A base plus config splits is not one file the installer in version 1.0.0 accepts. Installing the base alone is not a workaround I will stand behind.
  • XAPK and similar archives. Renaming to .apk does not change the contents. If the title is on Play, use Play. If it is your build, produce one APK from your build system.
  • A host folder you hoped would appear as storage. It will not. The image does not mount one.
  • A package you are trying to install onto the rooted Google APIs tablet while also expecting Play to know about it. Different tablet. The APIs image has no store. Root stays off unless you needed adb root for development.

The failure modes, with the boring detail, are in APKs that do not install or open.

A decision I can repeat

  1. Is the instance running, and is it the Play tablet? If you are staring at a stopped window, start it. If there is no Play Store icon, you are on the APIs image and this list’s Play steps do not apply.
  2. Is the title on Play and are you allowed to use that account? Install it from Play. Stop.
  3. Do you have exactly one .apk file? Cmd+I, or drop it, or adb install. Then try to open it.
  4. Did it fail immediately? Check split versus single, then ARM64, before you touch graphics or keymaps. A package that never installed cannot have a keymap problem.
  5. Did it open and then die? That is the app, or Play services, or a crash you can see in adb logcat. It is not a reason to try a third installer.
  6. Are you iterating on your own build beside Android Studio? Keep one emulator running and read SiliconPlay next to Studio before you collect two adb devices.

Replacing a store app with an APK, or the reverse

Android cares about the signing key. A store build and a sideload signed with another key will not install over each other. The error is Android’s, and the usual fix is to uninstall one of them. Uninstalling drops local data that was not in a cloud save. I cannot tell from here whether your game syncs. Open it, look, and then decide. I will not tell you a backup path inside the guest beyond /sdcard/SiliconPlay for files you put there yourself. A game’s private data directory is the game’s, and root on the other image is not a backup plan I am recommending for a Play title.

Where the file comes from

I am not going to link a pile of APK mirrors. If you do not know who built the file, do not install it. A repackaged game is how accounts get stolen, and it is how you end up debugging someone else’s malware on a tablet that is signed into a Google account you care about. Prefer Play. If the file is your build, you already know where it came from. If a tester handed you a single APK, ask them for the package name and the ABI before you spend an evening on a keymap for a file that cannot run.

Coming from another emulator does not change this choice. Their installer might have accepted an XAPK. This one does not. Reinstall from Play, or obtain a single ARM64 APK. The move is described in moving from another emulator.

FAQ

Is Cmd+I safer than Play?

No. It is a different door. Play is the right door for store titles. Cmd+I is the right door for a single APK you trust. Safety is about the file and the account, not about which shortcut you pressed.

Can I install from the Mac App Store?

No. The Mac App Store does not supply Android packages to this guest. Play is inside Android. The DMG is how you get the Mac app itself, from this site.

The APK installed and the icon does nothing.

Check for a missing ARM64 library, then logcat, then whether you are looking at the instance you installed to. A keymap will not revive a process that never started.

Can both be installed, Play copy and APK, under different package names?

If they are actually different packages, Android will treat them as different apps. If they share a package name, the signature rule above applies. I am not going to guess a specific game’s package name.
