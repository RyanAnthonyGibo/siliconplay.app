Android emulator on a Mac M1 or M4: step-by-step setup

By Ryan Gibo · 28 October 2026 · Updated 12 November 2026

If you searched for “Android emulator Mac M1” or “Android emulator Mac M4”, a lot of what comes up was written before Apple Silicon. This is the short, current version: how to get Android games and apps running on an M-series Mac with SiliconPlay, the app I build for Apple Silicon.

What you are installing

Underneath, SiliconPlay runs Google’s official Android Emulator, natively on the Mac’s ARM cores. The Mac app around it, the interface and the control mapping, I wrote from scratch. It is made only for Apple Silicon, from M1 through M6, and I have tested it on macOS Tahoe and macOS 27 Golden Gate.

What you need

  • A Mac with Apple silicon from M1 through M6 (Pro, Max and Ultra included).
  • macOS Tahoe and macOS 27 Golden Gate. Those are the versions I have tested.
  • A Google account, if you want to install from Google Play.

Setup, step by step

  1. Download SiliconPlay.dmg.
  2. Open the DMG and drag SiliconPlay to Applications.
  3. Open SiliconPlay and start Android.
  4. Sign in to Google Play and install your games and apps. To install an APK file instead, press Command-I.
  5. Click the Android image. Direct touch is the default. For keys, accept the preset SiliconPlay offers for your game, or apply MMORPG (WASD) and move the buttons.

The shortcuts to learn first

  • Command-I: import an APK and install it into Android.
  • F12 or Command-K: switch between Typing and Game keys.
  • Command-Shift-G: show or hide the on-screen game buttons.
  • Escape: leave fullscreen. Outside fullscreen it is Android Back.
  • Shift-Escape: release every virtual finger.

M1 or M4: what changes?

The app is the same on every chip from M1 through M6. I have not published per-chip benchmarks, so I will not give you numbers for an M1 or an M4. Newer chips have more headroom, which matters most in heavy 3D games. If a game stutters, lower its graphics settings first. Apps that ship without an ARM build will not run on any of them, but most current apps include one.

What the DMG does not contain

Dragging SiliconPlay to Applications installs the Mac app. It does not install Android. The first launch asks you to download Android and start. That accepts Google’s Android SDK license, then downloads command-line tools, the Apple silicon build of the emulator, platform-tools (that is where adb comes from), and the Play arm64 system image. The tablet it creates is landscape, 1920×1080 at 320 dpi, auto-rotate off, and named Android 16 Tablet.

If you already have an SDK from Android Studio or from the command-line tools, you can point SiliconPlay at that folder instead of downloading a second copy. The folder has to contain emulator, adb, and sdkmanager. A directory full of APKs is not an SDK. Pointing at another emulator’s private files will not import that emulator’s games. What does and does not come across is in moving from another emulator.

If setup stops and names a missing JDK, macOS is showing you the stub at /usr/bin/java. The message points at brew install openjdk@17. Install that, then run the package step again. Do not copy a random JDK into the SDK folder. Homebrew is not part of SiliconPlay. The sentence on screen is the one that matches your Mac.

Install a game only after the home screen is up

Cmd+I is the install shortcut, and it is the first one to learn. It imports a single APK into the running instance. Drag and drop is the same install. Neither works on a stopped instance. Split APKs and XAPK archives are not installed by this version. A package with no ARM64 build will not run on any chip in the supported list.

If the game is on Google Play, sign in on the Play tablet and install it there. The store is part of the Play image, not a store I put in the DMG. The Mac app never sees the password. Do not send the password to me. The rooted alternative is a different tablet: the Play image refuses adb root, so root is a second instance on the Google APIs image, and that image has no Play Store. You do not need it to play. Leave it off unless you are developing. The choice between the store and a file is Play or an APK.

Controls, after the game is actually installed

Click the Android image. Direct touch is the default, and it is a real way to play. A keymap stays unloaded until you accept it. The generic preset is MMORPG (WASD). It is not tied to one title. Apply it, then move the buttons onto the game’s controls. A controller drives those same buttons. Menus and text fields want direct touch or Typing, not the stick. F10 is direct touch. F12 or Command-K switches Typing and game keys. Command-Shift-G hides the overlay when it covers a button you need to see. Shift-Escape releases every virtual finger if one sticks. Escape leaves fullscreen, and outside fullscreen it is Android Back while the display is focused.

M1, M4, and the chips people ask about by name

Nothing in the steps changes for an M1, an M2, an M3, an M4, an M5, or an M6. I have not published per-chip frame rates, and I will not invent them to make this setup guide look precise. The one measurement I have published is from a MacBook Pro with M3 Max: up to 60 fps in a demanding 3D game, render resolutions up to 2560×1440, and 7–43 ms from key to game. Results vary by game, Mac, and settings. That 2560×1440 figure is not the tablet. The tablet is 1920×1080. If a game stutters, lower its graphics settings before you decide the chip is unsupported. Newer chips have more headroom. That is not a benchmark table. The longer version is settings by chip.

If setup still looks broken

  • The download was interrupted. A half-written image does not become a tablet. Let it finish into a folder you meant to keep.
  • You are installing into a stopped instance, or into the rooted tablet while looking at the Play window.
  • The file is a split set or an XAPK.
  • The keyboard is hitting the Mac because the Android image is not focused.

Walk the common problems in order before you reinstall the DMG. Reinstalling the app does not repair a bad SDK folder. The SDK folder stays on disk when you delete the app, on purpose. There is no kernel extension to remove.
